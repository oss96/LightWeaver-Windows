Play a link: where it lives

Owner: "the stream via url is gone." It is not gone from the code, only from sight. v2 still opens the WPF dialog on Ctrl+L (MainWindow.Files.cs, OpenStreamAsync), but nothing on screen leads to it, Settings › Keys leaves it out (SettingsPage.cs filters PlayerAction.OpenStream), and a link dragged onto the window is ignored (the drop handler takes files only). In the WPF shell it was a nav-rail entry, "Stream from URL", above Settings, which opened a page of its own.

What it isDetail
What the WPF feature tookA full http:// or https:// address with a host and no user name or password (StreamAddress.TryParse). A direct media file (mp4, mkv, webm) or a live or adaptive stream mpv opens on its own (HLS .m3u8, DASH .mpd, plain HTTP live streams). Web pages were refused in the copy ("rather than a webpage"). No history is kept, and queries and fragments stay out of titles and logs. Local files went through the separate Ctrl+O, a dropped file, or a path on the command line.
Jellyfin linksNo special handling. A Jellyfin stream URL plays only if it carries its own ApiKey (the ⋯ menu's "Copy stream URL" makes one). It then plays as an anonymous link: no resume, no progress reports, no metadata.
yt-dlpNever part of the feature. Before 2026-10-17 libmpv's default ytdl=yes could resolve a page link through a yt-dlp found on PATH. Since then ytdl=no (MpvPlayer.cs), so YouTube-style page links fail. None of the suggestions assumes yt-dlp.
PlaylistsWhatever mpv expands itself (an HLS master playlist, a remote .m3u). It never fills LightWeaver's queue. PlayUrl clears it.
What the player needsPlaybackController.PlayUrl(url, title?) needs a URL string and, optionally, a title. No auth header, no server item. It refuses while in a SyncPlay group ("Leave the group to open a local file or stream."). Without a title it uses the last path segment, or the host when the path is empty.

B5 · Arabic. The row mirrors, but the link stays a left-to-right run, as typed text in the field does.

  • What changes. When the field's trimmed text parses with StreamAddress, the search request is skipped and the 4a popup shows one row: the link glyph, "Play link", and the host and path in LwText2Brush, without the scheme, query or fragment. The row is 36 high, radius 4 and selected, as in 4a. Text with a scheme other than http(s), or with a user name or password, gets the same row disabled plus one 12 px LwErrorBrush line. Text with no scheme stays a search. Ctrl+L focuses the field and selects its text, as in a browser. The placeholder becomes "Search or paste a link" (de "Suchen oder Link einfügen", ar "ابحث أو الصق رابطًا"), which is shorter than today's string in all three languages.
  • Why. The search field is the one text box that is always on screen, and paste-and-Enter is the fastest route there is: no menu, no dialog. The popup and its keyboard handling already exist (Up/Down, Enter, Esc), so a link is just one more kind of row.
  • Cost. The field now has two jobs. The placeholder changes from the drawn string, and someone who never reads it will not find the feature.

Needed whichever suggestion is picked

  • A link failure gets its own cause and message (P4), and Info's play method says "Link", not "Downloaded file" (PlayUrl sets Player.LocalFile today).
  • The title follows the table above, and mpv's media-title replaces it when the stream has one.
  • Ctrl+L shows in Settings › Keys.

Candidates left out

  • Keyboard shortcut and a dialog, alone. That is v2 today, which is why the feature looks gone. A and B both keep the shortcut.
  • Downloads page. Downloads lists what is stored on this device. A link is neither stored nor a download, and the page would need a control that 08 does not draw.
  • The player's own menu. The player is only on screen while something plays, so it cannot start the first link. Its right group is full (13).
  • A new top-bar button. The bar is out of width at the 900 DIP minimum (the search field already gives up 40 DIP), and a button for a rarely used action is clutter.

Recommendation: B, with A's menu item pointing at it

B is the fastest route (paste, Enter) and adds nothing to any screen. To make it findable, take one item from A, "Play a link… Ctrl+L" in the profile menu, and have it focus the search field (B2) instead of opening a dialog. The dialog then goes away. C can come later as an extra for people who drag from a browser.
